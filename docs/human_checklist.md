## 2 — `MARGIN_MIN` 取哪档　⏱ 5 分钟

现在是 **1.25**。代价表在 `detector/attachment_detector.py` 的常量注释里，摘要：

```
floor   正确读数保住   冒名被拒
1.05      100.0%        6.6%
1.10       99.1%       13.3%
1.25       98.3%       27.6%      ← 现在
2.50       94.9%       83.7%
5.00       92.0%       92.1%      ← 再高只亏不赚
```

**这个闸赔掉的 33 次全部是 `supp_ar`**（DMR 上对 `supp_sr`，最薄 margin 1.05），占语料 1.7%。而且**拒答不引发错误动作**：`'?'` 走 `verifiable=False`，`ensure_kit` 报「证不了」不重试、不重拖。

### 活体实例（2026-08-05，人念的件名做真值）

mk14 刷出来自带的枪口，`loadout()` 连读三次都是 `'?'`。按出货裁图（`HUD_REGIONS['att_1_muzzle']`，63×63，`prefer='solved'`）实测：

```
Muzzle_Suppressor_Large_C          21.2   ← 人念的是「消音器 突击步枪」= 就是它
Muzzle_Suppressor_SniperRifle_C    23.6
Muzzle_FlashHider_SniperRifle_C   963.1   ← 第三名，远 45 倍
                                   margin = 1.11 < 1.25 → '?'
```

**检测器的第一名是对的**（人念的名字证实），只是 1.11 过不了 1.25。降到 1.05 这一格当场读对。

⚠ **它不是「缺模板」**，虽然长得一模一样。我一度把它列进【待采模板】和「mk14 cheek_pad 的阻塞项」，**两条都是错的**——两根灰管子再采一百张模板也还是一样，而 cheek_pad 那两格本来就要裸枪口，卸掉就没这回事。

### 取舍的真正形状

| floor | 失败时会怎样 |
|---|---|
| **1.25** | 拒答（`'?'`）→ `verifiable=False` → 调用方不动作。**安全** |
| **1.05** | 可能**报出错误的件名**。而错名是「真分歧」，会触发重试重拖 |

对**后坐力**这条线，认错影响约等于零——`supp_ar` 和 `supp_sr` 实测都是 null（akm 1.007 / m416 0.989 / mp5k 1.011 / vector 1.034）。对**装配校验**这条线，错名比拒答贵。

**我的建议是保持 1.25**，你只要认一下，或者说一句降到 1.05。

### vss 的一切 —— 根因不是 vss，是 `build_weapon` 从来不设 `scope`

`Weapon.set_seq` 里 `factor = scope_factor * naked_scale * att_f * posture_f`，而 `scope_factor` 只有 `set('scope', …)` 会写。`build_weapon` 设 name / posture / muzzle / grip——**没有 scope**。所以采集台在任何倍率下都在发**红点的曲线**。

|---|---|---|---|
| aug 红点 | 1741 | 1812 | **+4%** |

vss 自带的 PSO-1 在 `_SCOPE_TO_MAG` 里就是 4x，所以它一整天的「+111% 残差」同理——比值 3.26，接近 4。**为它试了 8 次、否掉 7 个解释、写了一整节文档，全部建立在那个误读上。**

**5. 姿势 × 配件的交互，两把 AR 符号相反。**
m416 装了件姿势收益**变小**（+13.8% / +21.6%），m762 **变大**（−6.2% / −7.0%），都在 3.7σ 以上。交互是硬的，**方向不是**。所以不能用一条修正曲线糊过去，而为什么不同没有解释。

**6. 重定时会让一格永远达不到满弹匣。**
