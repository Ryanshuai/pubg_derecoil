### 判定规则（可机械检查，这比目录名值钱）

4. `control/` 之外没有重试循环

### 关于 press/：终点是 HAL，不是入口

不要做成 facade（大家都调 `press.xxx()`），那会变成 god module。它是**最底下、被依赖、无策略、后端可替换**的那层。变薄的方式是搬走不属于它的东西，不是收拢更多进来。

`press/pointer.py` 一个文件装了两个不相干的东西：

| 行 | 内容 | 依赖 | 归属 |
|---|---|---|---|
| 43-253 | `game_focused` / `game_hwnd` / `raise_game` / `ensure_focus` / `FocusKeeper` | win32gui | **搬去 control/focus.py** |
| 261-367 | `Pointer`：move_to / click_at / drag | ctypes, pico_mouse | **留下** |

切口是干净的：`Pointer` 类内部一次都没调 focus 函数。搬走后 `win32gui`/`win32process` 会一起从 `press/` 消失，只剩 ctypes / serial / hid —— **这就是切对了的证据**。

`Pointer` 留下的理由：`click_at` 里那段 SetCursorPos → GetCursorPos 校验不是任务策略，是补齐驱动能力（Pico 只发相对 delta，绝对定位必须读回光标确认）。它不知道游戏存在。

### 关于「状态」这个词的两种含义

- **屏幕瞬时状态**（大厅在不在结算画面、spawner 哪列展开）→ **现测，永不缓存**。`LobbyControl.state()` 透传 `det.state()`、`SpawnerControl.sync()` 每次重读，这是对的，别改。危险写法是 `self._expanded = True`（我点过所以它是开的）—— 游戏会掉线、会弹窗、会被另一个 agent 抢走，缓存必然骗你。
- **游戏世界状态**（当前枪、配件、火力模式）→ 留在 `game_state.py`，在 control 之外。因为它不是每帧可观测，且 robot 和多个 control 要读同一份。**写入由观测驱动，不由「我发过这个动作」驱动。**

### dispatcher 的三块职责

| 行 | 内容 | 判定 |
|---|---|---|
| 61-203 | 表驱动 按键→改状态→推硬件 | 本职，留 |
| 204-273 | 调度检测器、结果写回 state | 本职，留 |
| 274-401 | mismatch 采集 | **搭车的，搬去 calibration/mismatch.py** |

mismatch 那块是训练数据管线（gt_mismatch / hard_case / attachment_conflict），**价值不动，只是换个文件住**。它搭在 dispatcher 上蹭现成的帧，导致这个文件同时是实时控制回路和数据标注器。剥出去之后 match 回路的延迟预算才可读 —— 现在磁盘写在控制线程附近，看代码看不出来它有没有拖到发 pattern 的时机。dispatcher 保留一个 hook 把帧和 detect 结果喂过去。

### 落地顺序（风险从低到高）

1. `focus` → `control/focus.py`（纯移动 + 改 import，press 立刻变纯）
2. 两个 control 换家：`detector/lobby_control.py` → `control/lobby.py`、`calibration/spawner_control.py` → `control/spawner.py`（纯移动）
3. mismatch 剥离（要验采集还在写盘）

## 2. control 动作拆分：去掉「每次都退回根节点」 🟡 离线部分完成，待实机验证

**已完成**：`detector/spawner_layout.expansions()`（绝对判据）· `PanelState` / `read()` / `goto()` / `collapse_all()` · `plan()` / `give_many()` · `pixi run panel-state`（44/44 帧真值回归）· 实测结论进 `docs/spawner/README.md` 3b 节。

**实测推翻了一个原假设**：原计划以为要处理「submenu 把下面的类别推走」，实际上 **42/42 帧显示类别行的 y 完全不动**——子菜单是覆盖绘制的。所以一次折叠态 `sync()` 的坐标永久有效，比预想的更好做。

**待实机验证**：`goto()` 的乐观单击策略、`give_many()` 的批量路径。离线测不到，因为它们依赖游戏对连续点击的反应。

### 现状问题

给两个不同类别的配件，要开面板 → 加 → 关 → 开 → 加 → 关。中间那次关闭是纯浪费。

**因果要反过来看**：不是「动作粒度太粗所以被迫回根」，是「状态判定只在根附近可靠，所以动作被迫做大」。

证据 —— `control/spawner.py:296`：

```python
def _is_expanded(self, shot, col):
    return column_diff(self.base_mask, bright_mask(shot), self.boxes[col]) > CHANGE_MIN
```

`base_mask` 是 `sync()` 时拍的**全折叠基线**。整个面板状态是**相对**它定义的，所以每个动作必须把面板还原成折叠态，否则下个动作没法判断自己在哪。`spawn()` 结尾那个无条件 `collapse()` 不是保守，是刚需。

而且基线会漂：`collapse()` 的注释已经写了 —— 东西掉地上，半透明面板背后的像素变了，基线失效，每个类别都读成「永远展开」。现在的补丁是拿 `find_submenu_items` 做二次确认。

**那个补丁里就是答案**：`find_submenu_items`（等间距居中行 = submenu）是**绝对**判据，不依赖历史。能自描述状态的东西已经有了，只是现在只当兜底用。

### 三层拆法

- **L0 原语** `click_category(col,row)` / `click_entry(e)` —— 只发点击，不读不验，无状态假设
- **L1 状态转移** `panel_state(shot)` → `{'open', 'expanded': (col,row)|None, 'entries'}`；`goto(node)` 读当前态、算最短路径、执行。唯一知道「这个菜单怎么走」的层
- **L2 意图** `give_attachment(key)` / `give_many([...])` —— 只说要什么，路径交给 L1

`panel_state` 用结构识别，**不用 base_mask**。一次截图就知道在树的哪个节点，不需要记得怎么来的 —— 这是能横跳的前提。

现在的 `spawn()`（`control/spawner.py:346`）把三层揉成一坨：同时是原语调度、状态机、意图入口，所以没法只改其中一层。

### 转移代价表

| 从 → 到 | 现在 | 应该 |
|---|---|---|
| 同类别再来一个 | 0（`expand()` 已有短路，这块没问题）| 0 |
| 同列换类别 | collapse + expand = 2 击 + 2 次截图验证 | 1 击 |
| 跨列 | 2 击 | 1~2 击 |

给 N 个不同类别的配件：现在 2N，改完 ~N。每次 collapse 都带 `shoot_parked()` + 重试循环，**省掉的截图和 sleep 比省掉的点击更值钱**。

> ⚠️ **待实测**：「点另一个类别会自动关掉前一个」是假设不是事实。手风琴 vs 多开是两种菜单，必须实测确认再写进 L1，结论记进 `docs/game_quirks.md`。

### 真正的大头是批量入口

`give_many(['Muzzle_X', 'Grip_Y', 'Stock_Z'])`：按 `(col,row)` 分组 → 排序让同类别相邻 → 一次遍历。这比「把逐个调用优化得更聪明」省得多，因为它从源头消除往返。

### 回根不删，降级成兜底

`sync()` 那套硬扛渐进绘制的逻辑（读到 stops changing）是血泪换来的，一行别动。变的只是地位：从**每个动作的必经之路**降级成 **L1 读不懂当前状态时的恢复路径**。乐观走捷径，看不懂就回根重来 —— 最坏不比现在差，常见情况快一倍。

### 范围：只做 spawner / tab

lobby 的 `ensure_mode` / `ensure_in_match` 是同一个模式，**但那边别改**。进出对局本来几十秒，省两次点击毫无意义，幂等回根换来的可靠性是实打实的。这个优化只对高频、低延迟的面板划算。

正面样板：`detector/tab_layout.py:278` 的 `slot_state(frame, gun, slot)` / `slot_map` 已经是「绝对可读状态」—— 不依赖任何基线，一帧自足。spawner 的 `panel_state` 照着写。

## 3. 截图沉淀：sidecar 元数据

### 现状（已经有 80%）

`tools/regression_check.py:46` 的 `_frames()`：递归扫 `docs/**/*.png`，尺寸等于全屏的自动纳入回归，不用注册。往 docs/ 一放就生效 —— **这个零登记设计是对的，要保留**。

### 三个卡点

1. **规则是隐式的**，只写在 `_frames()` 的实现里。「docs/ 下 + 尺寸对 = 进回归」，落在 `InGameScreenshot/`（万级）、`temp_debug/`（159 张）、`training_data/` 的就不进。哪张有用取决于它掉在哪，靠人记。
2. **只有全屏图能自动利用，裁剪图全废**。`docs/spawner/runs/*/col1_row01_label.png` 这类数量远超全屏图，而它们恰恰是模板匹配最想要的东西 —— 现在一张都没进管线。
3. **落盘时丢掉了免费的信息**。写 `cv2.imwrite` 那一刻 GameState 就在手边：哪把枪、哪些配件、哪个界面、这次标定期望是什么。存下来零成本，事后恢复只能靠人看图。**这条最值钱。**

### 方案

**a. 一个 `snap()` 替掉散落的 imwrite**

```python
snap(img, screen='spawner', kind='crop', roi=(y,x,h,w),
     parent='00_baseline.png', labels={'attachment': 'Muzzle_Suppressor_C'})
```

同名写 `.json` sidecar：

```json
{"ts": "20260802_153012", "kind": "crop", "roi": [1200, 2400, 64, 64],
 "parent": "00_baseline.png", "screen": "spawner",
 "state": {"slot1": "m762", "attachments": {}},
 "source": "calibrate-screen/spawner",
 "labels": {"attachment": "Muzzle_Suppressor_SniperRifle_C"}}
```

`state` 直接 dump GameState；标定脚本里 `labels` 就是它本来就知道的期望值。

**b. 回归改成查 sidecar，不猜尺寸**

- `kind=full` → 全套 detector，比 baseline（现有 52 帧行为不变）
- `kind=crop` + 有 `labels` → 只跑对应 detector，**断言等于标注**

质变：现在的断言是「跟上次一样」（只能抓依赖升级的漂移），加标注后是「跟真值一样」（能抓真错）。那堆裁剪图立刻从死数据变成测试集。没 sidecar 的老图保留尺寸兜底，不破坏存量。

**c. 模板自动重建 `tools/build_templates.py`**

扫所有 `kind=crop && labels.X == 名字` 的图 → 按名字聚合、对齐取中位数 → 写 `training_data/<detector>/<名字>.png`。新枪新配件走一次标定，模板自己就有了。接上 `calibrate-template` skill：skill 负责采，这个负责入库。

**d. debug 复盘 `tools/replay.py <图或run目录>`**

跑全套 detector，结果画回图上；sidecar 有 labels 就把不一致的标红。排查「这张图为什么认错」从手写脚本变成一条命令。

### 边界

- `InGameScreenshot/` 那上万张是训练数据，这套机制不碰
- `temp_debug/` 那 159 张可以补录 sidecar 后并入 docs/，但**原文件不删，只做复制**

### 落地顺序

1. `snap()` + sidecar 格式，只在新采集点用，不动存量 —— 这步就能立刻止血
2. 给存量补 sidecar（`kind`/`screen`/`roi` 能从尺寸和路径反推，`state` 留空）
3. 回归读 sidecar，裁剪图入网
4. `build_templates`

### 先说好消息：底层已经是对的

`control/inventory.py`（注意：`give_attachment` 的 docstring 里写的 `tools/control/inventory.py` 是过时路径，顺手改掉）地址已经是一等公民：

```
at_ground(i)     row i of 附近/地面    ('nearby', i)
at_inv(i)        row i of 库存         ('inventory', i)
at_slot(g, s)    枪 g 的 s 号配件槽     ('weapon', g, s)
```

唯一原语 `drag(src, dst)` 接受任意地址对，模块 docstring 里就写着 `ac.drag(at_slot(1,'scope'), at_slot(2,'scope'))  # gun 1 -> gun 2`。

所以「配件必须经背包中转」**其实已经不成立了**，只是不好发现：

| 想做的 | 现在就能写 |
|---|---|
| 枪上 → 地上 | `ac.discard(at_slot(1,'muzzle'))`（docstring: "Works from a slot too"）|
| 枪上 → 地上（另一种）| `ac.unequip(1, 'muzzle', to=at_ground())` —— `to` 本来就是参数 |
| 地上 → 枪上 | `ac.equip(1, 'muzzle', at_ground(3))` |
| 整枪拆光扔地 | `ac.strip(1, to=at_ground())` |
| 枪 1 → 枪 2 | `ac.drag(at_slot(1,'scope'), at_slot(2,'scope'))` |

**要做的不是加路径，是让这些路径可发现** —— 见下面「接口好组合」。

### 真正缺的：枪本身不是一个可拖拽地址

地址空间里 `('weapon', gun, slot)` 是**配件槽**，没有表示**枪本身**的地址。所以「把枪连配件一起扔地上」这条路现在写不出来，只能 `strip()` 逐槽拆完再扔。

要加：

```python
at_gun(g)                     # ('weapon', g) —— 枪本身，不带 slot
ac.drag(at_gun(2), at_ground())     # 整把带配件扔地上
ac.drag(at_ground(0), at_gun(2))    # 地上整把捡进 2 号位
```

坐标可以从 `detector/tab_layout.py:151` 的 `equip_region(name)` 拿。

**验证方式要跟着变**：现在 `drag(want=...)` 是逐槽比对模板。扔整枪之后该断言的是「2 号位空了」+「配件没出现在库存里」，而不是逐槽验证 —— 逐槽验证在枪已经不在了的情况下没有意义。

### 接口好组合（用户的核心诉求）

目标：别的 agent / 组合脚本拼流程的时候顺手，不用读实现。三件事：

**a. 能力矩阵从 docstring 变成可查的数据**

现在「哪些 src → dst 组合合法」只写在模块 docstring 的散文里。做成一张表，`drag()` 用它做前置校验，同时别的 agent 可以直接读：

```python
MOVES = {('weapon_slot', 'ground'): ..., ('ground', 'weapon_slot'): ...,
         ('gun', 'ground'): {'carries_attachments': True}, ...}
```

**b. 统一返回记录**

### 5g 已完成：帧源统一到 `ScreenBuffer`

`sweep.Rig` / `state.Probe` / `capture_ads.grab()` 都换成了 `detector/cropper.ScreenBuffer`（`harvest.Panel` 那份在 5f 里随类一起删了）。三份「crop 贴回全屏 buffer」和三份 icon 包围盒计算归一。

顺带修掉一处一直在做无用功的地方：`Probe.read()` 原来先单独 blit 一次 spawner，接着 `_full()` 又把**包括 spawner 在内的所有区域**再 blit 一遍——两个调用互相不知道。现在一次 `full()`，两个按屏幕坐标索引的检测器共用。

**唯一要改控制流的一处，也是这一步真正的内容：失焦。**

`ScreenBuffer(focus_fn=game_focused)` 之后 `grab()` 会在游戏离开前台时**抛 `FocusLost`**，而不是把 PUBG 留在屏幕上的那张冻结画面递回来。这修的是一个静默故障：run 一路抓下去，测的是一张静止图，报回来一个漂亮得可疑的残差。

代价是两处必须跟着改，否则修复本身会变成新的故障：

1. **扳机。** `fire_magazine` 的采集循环按住左键最长 `MAX_FIRE_S`。异常从中间逃出去，按键就一直按着——角色对着一个没人看的窗口继续开火，穿过换弹，进入下一个 cell。现在整个循环包在 `try` 里，释放在 `finally`。
2. **弹匣层。** `calibrate_combo` 和 `measure_cell` 各接一个 `except FocusLost`：丢掉这发弹匣、`focus_keeper().ok()` 抢回焦点、`flush(6)`、继续。**弹匣没了，cell 还在。** harvest 一轮 45–50 分钟而终端会自己把焦点抢回去，这是「少一发弹匣」和「少一整轮」的区别。

`state.py` **不传** `focus_fn`，这条是刻意的：那个工具的全部承诺就是任何时刻都能安全跑（包括在猜别的 agent 是不是正占着游戏的时候），而且它本来就把 focus 当成一项**读数**打印出来。加守卫等于让它在最需要它的时刻拒绝工作。

`capture_ads` 的整屏模式是一个**有名字的分支**而不是隐式优化：无区域时 `full()` 每次返回**新数组**，而 `capture_scope` 留着 `hip` 帧去 diff 后面的帧、`_watch` 留着抽稀的副本。共享 buffer 会让这些悄悄变成同一张图。往那个 ScreenBuffer 里加第二个区域就会拿掉快路径并让它们互相别名——注释里写死了。

`rig.grabber` / `rig.paced` 保留为 property 别名（两处诊断打印在读），不是拷贝：`set_sight` 会在底下换掉区域集，拷贝会让改动那一轮的日志报出错误的后端名。

**`pixi run frames` 的 AST 对拍退役了。** 它把包围盒算法从每份手写副本里抽出来重跑，好让「迁移把盒子挪了一个像素」必须在这里失败。两份副本现在都没了（Panel 随类删除，Probe 改调 `anchor_box()`），它没有第二个意见可以提供。**它在路过时抓到了这两次删除，这正是它的用途。** 是故意删掉而不是改成能容忍找不到名字——一个对「类没了」耸肩的查找，会正好静默通过它本来要守的那次迁移。替代品更弱，注释里明说了：盒子被钉在实测字面量上，所以改 `anchor_box()` 或 `SPAWNER_ICON_*` 仍然会失败，但一个自己另算盒子的调用方不会。**再出现第二份副本，就把 AST 检查请回来。**
