# 压枪时序：谁在什么时候发生

每一次"第一发不压枪"最后都查到这里。这份文档记的是**实测值和推导**，不是设计意图。

## 符号

| 符号 | 含义 | 谁能测 |
|---|---|---|
| **P** | 指令发出 → 该指令在**画面上**生效（USB + 输入采样 + 模拟 + 渲染 + 呈现） | 测不到，也**不需要** |
| **C** | 画面上成立 → **我们**从抓帧里看到（DXGI + 我们的循环） | 测不到，也**不需要** |
| **W** | 扳机被识别 → 子弹离膛（枪自身的击发延迟） | 见下 |
| **T** | 弹间隔 = 60 / RPM | 弹药计数器的斜率 |
| **L** | = P + C，我们发 move 到我们看见视角动 | `tools/probe_input_latency.py` |
| **S** | = W + P + C，我们发 click 到我们看见计数器跳 | `tools/probe_shot_latency.py` |

## 实测（2026-08-02，AUG，红点，训练场）

```
L = 38 ms   (n=44, sd 4.8)      两轮：35.8±5.1 和 39.7±4.5
S = 51 ms   (n=36, sd 8.1)      两轮：51.9±8.5 和 49.5±7.8
W = S − L = 13 ms
```

**S 必须从弹药计数器量，不能从"视角开始动"量。** 两个都记了：计数器是**阶跃**，第一帧看到就是答案；后坐力是**斜坡**（AUG 一发的前 7ms 只有 0.9 counts，中段 2.7），任何位移阈值都会晚一到两帧触发。实测 gap 是**单边**的——16 次里 7 次同帧，**一次都没有后坐力更早**。这是判据的形状，不是两件事真的错开。

**推论：计数器跳变和后坐力起始是同时的。** 这一条撑着两件事：`fit_curve` 可以拿"第一次计数器跳变"当 bin 原点而让捕获延迟自动抵消；以及下面这个推导能闭合。

## 推导：图案该在什么时候放

固件把第 k 个点排在点击后 `t_k`，这些 counts 在 `t_k + P` 上屏。
第 k 发的后坐力在 `W + P + k·T` 上屏。令二者相等：

```
t_k = W + k·T
```

**P 和 C 全部消掉了。** 渲染管线延迟、捕获延迟都不进这个式子——**只有枪自身的 W 进**。

铺开区间同样对齐：固件把第 k 个点铺在 `[t_k, t_k + T]`，上屏后是 `[W+kT, W+(k+1)T]`，正好是那一发后坐力占的窗口。**所以没有半间隔修正项。**

`press/pico_mouse.RECOIL_FIRE_DELAY_MS = 13`（毫秒，不是弹间隔的比例——USB、输入采样、开火动画不会因为枪射得快就变快）。

## 后坐力在一发之内的形状

`tools/probe_kick_profile.py`，关补偿，把整梭的逐帧位移折叠到一个弹间隔上。AUG，88ms 分 12 段：

```
0.9  1.3  0.7  2.7  2.5  2.3  2.2  1.9  1.6  1.2  1.2  1.4     合计 19.9 counts
```

**单调爬升，铺满整个间隔，没有"猛顶再回落"。** 这一条直接决定了上面那个"没有半间隔项"的结论——如果后坐力是脉冲，两边重心就不会一起动。

采这个数据必须**先把准星压低**（`--aim-down`）：关了补偿的 AUG 每发抬 20 counts，五发就把视角推出可跟踪范围，之后测到的 −0.9 counts 不是"后坐力温和"，是**没有纹理**。

## 错过三次的地方

1. **`RECOIL_LEAD_FRAC = 0.30`** —— 把图案按弹间隔的比例**提前**。符号错、单位错、从没测过。
2. **`36 − T/2`** —— 36 来自 S=72（用粗阈值量后坐力起始，系统性偏晚）；`−T/2` 来自"用 ramp 抵消**脉冲**要把误差居中"，而后坐力不是脉冲。AUG 上合计早了 44ms，正好半发。第一发的时间还被 clamp 到 0，补偿在子弹出膛前就发完了大半。
3. **残差看不出以上任何一条。** 拟合用的 bin 锚在计数器上，固件放曲线锚在点击上——**两个不同的原点**。拟合会收敛到"在自己那个网格上残差为零"的曲线：自洽、扭曲、而且屏幕照样跳。**残差为零 ≠ 屏幕不动。**

## 第一发：实测过了，而且它是**最干净**的那一发

2026-08-03，`tools/probe_impulse_ab.py`，AUG，红点，3 轮 × 3 个弹匣。

在这之前脉冲测试只验过第 12 发和第 30 发，两个都是稳态。第 0 发是瞬态——点击边沿、图案上传、扳机按下、开镜稳定、枪口火光全挤在那个窗口——所以一直没测，理由是"那儿噪声大"。

**这个理由是错的，而且错在关键方向上。**

测法是 A/B 差分：同一梭打两次，一次全零曲线、一次只有第 k 发有 120 counts 的尖峰，逐发位移相减。游戏自己的后坐力、开镜稳定、首发瞬态在两次里都有，被减掉了。

三轮，各 3 梭对照 + 3 梭 k=0 + 3 梭 k=12。命令的尖峰是 −120 counts：

| run | 基线曲线 | 第 0 发 | 第 12 发 |
|---|---|---|---|
| `ab_aug_0803_0050` | 全零 | 落 0，**−116** | 落 12，−83 |
| `ab_aug_0803_0107` | 全零 | 落 0，**−109** | 落 12，−105 |
| `ab_aug_0803_0125` | 存储曲线 | 落 0，**−99** | 落 12，−100 |

**三轮都落在命令的那一发上。第一发有压枪，`t_k = W + k·T` 在 k=0 成立，不需要特殊处理。**

### 一条写错又撤回的推论

第一轮里第 12 发比第 0 发脏（−83 对 −116，前泄 20% 对 5%），我据此写过一段"间隔误差累积"的解释，还算了预测泄漏 11%。

**它没复现。** 第二轮 −109/−105、第三轮 −99/−100，两边对称。那个不对称是 n=1 的噪声，而我给它配了一个机制、一个数量级、和一条"以后要在第 0 发验对齐"的结论。**机制和数字都撤回。**

保留的只有先验部分，而且它是推理不是实测：第 0 发按定义没有累积的间隔误差，所以它是唯一能把"偏移错了"和"间隔错了"分开的位置。要拿它当判据，得先真的观测到两者分离。

### 过程质量：三轮之间修了两件事

| | 0050 | 0107 | 0125 |
|---|---|---|---|
| `did not follow`（视角飞到天上，相位相关读 0） | 5 | 4 | **0** |
| 参考定位可用 | 否 | 否 | **是** |

两个原因，都跟时序无关：

1. **基线曲线不该是全零。** 差分只要求 A/B 两次**相同**，不要求是零。用全零打满 40 发，AUG 爬 883 counts = 1366 px = **5.3 个 patch 高**，视角进天上后没纹理，相位相关自信地返回 0，`track_still()` 累计不出东西，`pending_pitch` 降不下来。换成这把枪自己的曲线当基线就没了。
2. **探针从没调用 `set_reference()`。** `ref_patches` 是 `None`，`absolute_offset()` 第一行返回 `None`，于是每梭都报"cannot place"——而那句信息当时写的是"离参考超过 N counts，或场景变了"，**断言了一个它没检查过的原因**。为此白跑了两轮、还做了一次针对不存在的量程问题的修改。四种拒绝理由现在各有各的话。

### 又一条写错又撤回的推论：方向反了

当时顺带写下："存储的 AUG 曲线前 16 发合计 436 counts（27/发），零压枪实测同区间 +272（17/发）——命令比实际后坐力多 60%，全弹匣 1398 对 ~880。"

**测了，是反的。** 2026-08-03 02:31，AUG／裸枪／红点／开 homing，4 梭全部 `oor=0 hand=0`：

| | 命令 | 残差 | 真实后坐力 |
|---|---|---|---|
| mag 0 | 1398 | **+526** | |
| mag 1 | 1451 | **+390** | |
| mag 2 | 1490 | **+361** | |
| mag 4 | 1521 | **+353** | |
| 合计 | | +407 ± 70 | **1958 counts / 42 发** |

残差**每一梭都是正的**：曲线**压不够**，差约 560 counts（29%），不是多压 500。

错在哪：那个 "~880" 来自零压枪那轮，而**本文档上面第 53 行自己就写着**关补偿的 AUG 五发就把视角推出可跟踪范围、之后测到的是"没有纹理"而不是"后坐力温和"。我引了这句警告，然后用了它警告的那个数。

所以 `view will not come back` 的原因还是量程——每梭 ~400 counts 的净漂移对 83 counts 的参考量程——但**方向是往上，不是往下**。修法不变（重测曲线），归因改了。

顺带两个数也是这轮才对上的：**弹匣 42 发**（ext_ar），射速本轮重新计时（那个值后来发现是从单个弹匣存的，见下面「射速是从一个弹匣存进去的」，已改成 **722.6**）。

### ⚠ 一条没解释的矛盾，记着别忘

同一天 02:50 的脉冲 A/B（`docs/impulse/ab_aug_0803_0250.json`）里，视角是**往下**漂的：
每梭约 −85 counts，三梭累计把 `pending_pitch` 推到 −861，recenter 撞上下方 clamp

而 harvest 是 42；曲线中间被 EMA 从 1398 抬到了 1551。两条都不足以解释符号翻转。

**不给机制。** 今天已经有两次给 n=1 的现象配机制然后被自己的数据推翻（第 12 发前泄、

## 固件里三个相关的坑

`press/firmware/src/main.c`：

- **`rng_float()` 返回 [0, 2)，不是注释说的 [−1, +1]**（`& 0xFFFF` 已经清掉符号位）。所谓"抖动"因此是单向偏置：幅度 `×(1+0.02·rng)` 均值 **+2%**，偏移 `+0.2·rng` 每发**恒定多压** 0–0.4 counts。AUG 整梭多压约 29 counts，EMA 一直在把它吸进曲线。第一发补偿只有 0.68 counts，那个 +0.4 是 60% 的扰动。
- **最后一发的铺开窗口写死 100ms**，跟射速无关。Vector 间隔 54.5ms，最后一发（后坐力最大的一发）被抹成近两发宽。改成用前一个间隔。
- `get_recoil_delta()` 在 `send_hid_output()` 里**先于**开火检测被调用，所以点击那一毫秒 `firing` 还是 false。`t_0 = 13ms > 0` 之后这条不再有影响。

### 射速是从**一个**弹匣存进去的（2026-08-03 修）

`interval_from_span` 的 docstring 自己写着要防的那件事：

> 漏掉最后一次跳变会缩短跨度，读成"枪更快"。它表现为**同一格里各弹匣互相不一致**，所以调用方存之前应当先要求一致。

**没有任何调用方做这件事。** 重测 AUG 那轮，第 3 梭读到 81.32 ms，当场写进 `weapon_rpm.json` 成了 **737.9 rpm**；而前后四个被保留的弹匣读的是 82.73 / 82.93 / 83.08 / 83.39 ms（719.5–725.2 rpm）。存下来的 `fit_resid_ms` 是 **0.0**——两端点求间隔按定义没有残差，于是 `rpm_store.acceptable()` 拿 0.0 跟 12 ms 比，什么都拦不住。

2% 的间隔误差在 42 发弹匣尾部就是差不多一发的相位，而拟合会把这个相位当后坐力吃进去。

改法：**重新计时照旧当场生效**（那一梭本来就在错的网格上打，丢掉是对的），但**不落盘**；落盘挪到一格结束、从互相一致的弹匣求平均，存进去的 `fit_resid_ms` 换成**弹匣之间的离散度**——一个真的可能过大的数。阈值 `rpm_store.AGREE_MS = 1.0 ms`，是推出来的：间隔误差 d 会累积，第 k 发晚 `k·d/T` 发，`41×1.0/83 = 0.49` 发，正好等于脉冲检查允许的半发。

实测尺度：那四梭的离散度是 **0.24 ms**。

AUG 已按新方法重存：**722.6 rpm**（4 梭 / 168 发）。

**当前阻塞**：弹药计数器**开火时读不出来**——静止 40/40，开火中一梭 42 发只读到 5 次。射速拟合因此拿不到数据。`sweep.Rig.ammo_debug_dir` 设了目录就会把读失败的 crop 存下来。
