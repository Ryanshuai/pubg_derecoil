## 修一个静默故障，要跟着改它下游的控制流

`ScreenBuffer(focus_fn=game_focused)` 让 `grab()` 在游戏离开前台时抛 `FocusLost`，
而不是把 PUBG 留在屏幕上那张**冻结画面**递回来（原故障：run 一路抓下去，测的是
一张静止图，报回来一个漂亮得可疑的残差）。

**代价是两处必须跟着改，否则修复本身变成新的故障：**

1. **扳机。** `fire_magazine` 按住左键最长 `MAX_FIRE_S`。异常从中间逃出去，
   按键就一直按着——角色对着一个没人看的窗口继续开火，穿过换弹，进入下一个 cell。
   现在整个循环包在 `try` 里，释放在 `finally`。
2. **弹匣层。** 各接一个 `except FocusLost`：丢掉这发弹匣、抢回焦点、`flush(6)`、
   继续。**弹匣没了，cell 还在**——harvest 一轮 45–50 分钟，这是「少一发弹匣」和
   「少一整轮」的区别。

`state.py` **不传** `focus_fn`，刻意的：它的全部承诺就是任何时刻都能安全跑，
而且它本来就把 focus 当成一项**读数**打印。加守卫等于让它在最需要它的时刻拒绝工作。

**失焦控制流故意不在实机上验**，改成 `pixi run fire`：要在真游戏上证明它，就得
在开火中途故意抢焦点，而**万一守卫是坏的，那一次运行正好就是把扳机按住不放的
那次**。

显然的实现是每槽一次直拖 `at_slot(1,s) → at_slot(2,s)`。没走，因为**隔壁的实测

如果那个失败是**落点**的问题而不是源的问题，直拖同样会坏——而且是**静默地**坏：
件留在原处，只有读回才知道。所以走的是每个手势都被量过的路线。

| `measured` | 有探针跑过，数字在 `docs/game_quirks.md` |
| `used` | 没专门探针，但标定 run 天天走这条路，坏了会响 |
| `untested` | 相信它存在，从没确认过。`transfer()` **拒绝默认走这种** |

**闸门的价值**：两端都是合法地址不代表这个动作存在。`('gun','inventory')` 是两个
好地址加一个不存在的动作，原来会作为一次真实的 1600 px 拖拽发出去然后报「拖拽
失败」。

跟 `_reject()` 不认识 `('gun', n)` 那个洞是同一个形状：地址、抓取点、`point_of`、
`drop_weapon` 全都写好了，只差校验器那一个分支，于是**这个功能从加进来的那天起
就没工作过**——而每次扔枪都在鼠标动之前被拒，报的却是「拖拽失败」。**症状说的是
手势，成因在词汇表。**

## 一个批次没有失败的步骤，不等于它成功了

`all([])` 是 True。一个还没走到第一步的批次没有失败的步骤可指。
`pixi run locations` 钉着这条。

相关的一条刻意偏离（写在 `batch()` 的 docstring 里）：`ensure_kit` 的 `ok` 由
**读回**决定不由步骤决定，那是**更强**的判据——一次换件可以报告拖拽干净而槽位
里躺着别的东西，而「每一步都 ok」恰恰是没人会再看一眼的情形。所以
`batch(ok=...)` 允许覆盖成更强的，**永远不允许覆盖成更弱的**。

## 删一个测试，比让它对「找不到」耸肩要好

`pixi run frames` 有过一个 AST 对拍：把包围盒算法从每份手写副本里抽出来重跑，
好让「迁移把盒子挪了一个像素」必须在这里失败。两份副本后来都没了，它没有第二个
意见可以提供了。

**是故意删掉而不是改成能容忍找不到名字**——一个对「类没了」耸肩的查找，会正好
静默通过它本来要守的那次迁移。替代品更弱，注释里明说了。**再出现第二份副本，
就把 AST 检查请回来。**

## 留壳会让没人迁

5n 把 `stocktake` 整体搬进 `control/stock.py`，**CLI 整体搬走，没留壳**。理由写在
那个文件的 CLI 段：留个壳会让 `from stocktake import ...` 继续能解析，而**能解析
的 import 没人会去迁**。且留壳会制造一条 control→calibration 的**反向依赖**。
